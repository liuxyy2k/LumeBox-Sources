# 十八漫画图片加载修复记录

日期：2026-10-15。范围：公开列表、详情及章节图片的兼容性排查；未涉及账户、付费或访问权限变更。

## 结论

列表和章节 HTML 可正常取得，但业务图片返回整文件 AES-CBC 密文。源脚本此前仅返回图片 URL，App 直接尝试解码密文，导致封面占位、正文加载失败。

## 证据 → 发现 → 修复路径

| 证据 | 发现 | 修复路径 |
| --- | --- | --- |
| E-001：列表、详情和章节响应均为 HTTP 200，章节解析出 22 张图片 | HTML 解析并非本次样本的阻断位置 | 保留现有列表、章节解析 |
| E-002：封面及正文图片响应为 binary/octet-stream，首 16 字节均无 JPEG 文件头，完整长度分别为 528208 和 528736 字节 | 返回体是编码数据，不能直接交给 Flutter 图片解码 | 按站点公开图片处理流程还原 |
| E-003：公开 `plugins/lazyload.js` 中 CRYPTO_CONFIG 指定 CBC、NoPadding；decrypt_base64_str 对常规明文图片直接返回 | 与已有 AES-CBC/PKCS7 模式不同，混合明文不能重复解密 | 新增独立 aes-cbc-nopadding 模式，保留既有模式 |
| E-004：App 解码后，Flutter 实际解码样本得到 1302×1920 封面和 1337×1920 正文图片 | 还原结果是可显示的图片数据 | 源脚本为列表、首页、详情和正文提供本地解码元信息 |

公开脚本：[comic_chapter_main.js](https://18mh.net/static/frontend/js/comic_chapter_main.js)、[plugins/lazyload.js](https://18mh.net/static/frontend/js/plugins/lazyload.js)。前者加载后者，图片经 fetch、FileReader、decrypt_image_blob、decrypt_base64_str 转为 Blob。此次通过 HTTP 实际响应、公开脚本和本地独立 Node/Flutter 复现核对，未采集浏览器调用栈。

临时原始响应及真实图片仅用于本地验证，没有提交到仓库；签名 URL 未写入本记录。

## 改动与验证

- `comic/十八漫画.js` 版本升为 1.0.2，为图片提供 `X-Lume-Image-*` 元信息，保留图片签名参数。
- App 的 `image_bytes_decoder.dart` 增加 NoPadding 模式，检查还原后的图片文件头；明文图片直接保留。
- 这些元信息由 App 本地消费，图片网络管线原有过滤规则禁止将其发给图床。
- Node 回归：`node --test tools/mh18_image_regression_test.js tools/source_names_test.js`。
- App 回归：`flutter test --no-pub test/image_bytes_decoder_test.dart`；其中密文由独立 Node crypto 生成，使用无内容的一像素 PNG 测试。
- 实际样本的 Flutter 解码已通过；这不等同于手机端逐章节验收，也不能保证未来站点不更换参数。

## 交付限制

新源与新增 App 解码模式配套使用。按照用户要求，本次不构建安装包；手机端须等待用户明确要求的下一次出包后验证。公开源文件可通过订阅更新，但旧版 App 不具备新增解码模式。
